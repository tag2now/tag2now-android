# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Android app for **tag2now**: a Trusted Web Activity (TWA) that opens
`https://match.tag2now.click` in Chrome without an address bar. There is no app
code here — the screens are the website, so a web deploy reaches the app with no
rebuild. Rebuild only when the icon, name, colours or Android settings change.

Generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
(`@bubblewrap/cli@1.27.0`). `twa-manifest.json` is the source of truth; `app/`
and the Gradle files are generated from it but tracked, so edits made after
generation show up in a diff.

| | |
|---|---|
| Package ID | `click.tag2now.twa` — permanent; a new ID is a new app |
| Host | `match.tag2now.click` (no trailing slash) |
| minSdk | 24 |
| Distribution | APK sideload only, so far |

## Building

Bubblewrap keeps its own JDK 17 and Android SDK; `~/.bubblewrap/config.json`
points at them. `build` asks for the keystore and key passwords, so it runs in a
terminal the user types into — never pass the passwords on a command line.

**In the Claude desktop app's terminal, run Bubblewrap through `cmd`:**

```bash
cmd /c "set NoDefaultCurrentDirectoryInExePath=&& npx -y @bubblewrap/cli@1.27.0 build --skipPwaValidation"
```

That terminal sets `NoDefaultCurrentDirectoryInExePath`, so cmd does not look in
the current directory and Bubblewrap's bare `gradlew.bat` is "not recognized".
Windows checks only that the variable exists: `$env:… = ''` in PowerShell 7.5
leaves it set as an empty string and fails the same way. cmd's `set X=` removes it.

Output: `app-release-signed.apk` (sideload) and `app-release-bundle.aab` (Play).

### Changing settings

Edit `twa-manifest.json`, then regenerate:

```bash
npx -y @bubblewrap/cli@1.27.0 update
```

`update` bumps `appVersionCode`/`appVersionName` unless `--skipVersionUpgrade`
is passed; an installed app only accepts a higher version code. It also fetches
`webManifestUrl` and the icon URLs, so those must point at production.

**Re-apply `minSdkVersion 24` after every `update`.** Bubblewrap 1.27.0's template
writes 21, which `androidbrowserhelper` 2.7.4 refuses at the manifest merge.
`twa-manifest.json` already says 24; check `app/build.gradle` says it too.

`build` compares `manifest-checksum.txt` with a SHA-1 of `twa-manifest.json` and
offers to regenerate when they differ. Commit both together.

## Signing and the address bar

`android.keystore` (alias `android`) is **not in git** and must be backed up
outside it, with its passwords. Every update must be signed by the same key.

Chrome hides the address bar only after it verifies
`https://match.tag2now.click/.well-known/assetlinks.json`, which lives in
**tag2now-FE** (`public/.well-known/assetlinks.json`) and lists this package and
the key's SHA-256. Read the fingerprint from a built APK — no password needed:

```bash
keytool -printcert -jarfile app-release-signed.apk
```

A new key, or Play App Signing (Google re-signs with its own key), means adding
that fingerprint to the FE file and deploying FE. Until then the app opens with
an address bar — it still works, as a Custom Tab.

Verify what Chrome will see:

```bash
curl "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://match.tag2now.click&relation=delegate_permission/common.handle_all_urls"
```

## Trying it on the emulator

```bash
adb install -r app-release-signed.apk
adb shell monkey -p click.tag2now.twa -c android.intent.category.LAUNCHER 1
```

A fresh emulator shows Chrome's first-run screen before the app; a real phone
with Chrome set up does not. Chrome caches the asset-links result, so after
changing the FE file, reinstall the app to re-check.
